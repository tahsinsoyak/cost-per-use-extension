# Cost Per Use v1.1.0

## New purchase-planning features

- Compare expected cost per use with half as much use over the same ownership period and net cost.
- Set an optional cost-per-use target and see the minimum whole uses needed to reach it.
- See neutral usage estimates in results and history instead of labels that suggest whether you can afford a purchase.
- Use the new features and update notice in all ten interface languages, including Arabic right-to-left layout.

## Reliability fixes

- Reject negative and non-finite costs, incomplete installment plans, fractional installment counts, and usage estimates that cannot produce a meaningful result.
- Check resale against the actual financed total plus maintenance, rather than only the cash price.
- Recalculate imported results from validated inputs instead of trusting supplied totals. Invalid records are skipped; an import with no valid records leaves history unchanged.
- Restore installment and hourly-wage values when loading saved calculations.
- Associate form labels and error messages with their controls and accept decimal amounts in advanced fields.

## Data and compatibility

Existing saved history and settings are retained. The temporary target is not saved in history and resets when calculating again or leaving the calculator. Imported valid records retain their IDs and timestamps; their calculated values are recomputed. The same three permissions are used: `storage`, `scripting`, and `activeTab`. No analytics, accounts, cloud sync, new data collection, or remote code were added.

The optional product reader runs only when auto-fill is enabled and the extension is opened on a page. The website is available at [Cost Per Use](https://tahsinsoyak.github.io/cost-per-use-extension/).

## Release verification

Run `npm run release:check` for the complete repeatable pipeline. It runs unit and locale tests, builds and validates the package, validates Store assets, checks scenarios, targets and the update notice in all ten languages and both themes, and tests the built extension in an isolated Chromium profile. The built-extension checks include Chrome storage, comparison limits, history restoration, JSON import/export, and the real toolbar action with `activeTab` autofill against a local product fixture.

The fixture proves the extension's permission and autofill flow; it does not guarantee that every live shopping site's markup will remain compatible. Test your usual product pages when reviewing the unpacked build.

See the [upload guide](../chrome-web-store/releases/v1.1.0.md) for the package and dashboard steps.
