# Growing Cost Per Use after 1.1.0

The public Chrome Web Store listing showed version 1.1.0, four users, and no ratings on October 17, 2026. The developer previously reported 131 Store impressions and 40 page views for a longer period ending in September. Those periods and measures differ, so they do not establish a conversion rate or a growth trend. Use fresh, matching date ranges in the dashboard before deciding where users drop off.

## First: make the first use dependable

For the next extension version, finish and review the [broader product reader](product-reader.md). Then fix the known comparison issue when products use different currencies, prevent saving a result after its inputs change, and surface storage failures. Test upgrades using saved 1.0.2 and 1.1.0 data. Accurate results and preserved history matter more than adding many store names to the listing.

## Then: improve discovery and trial

1. Keep the Store title and summary plain: what the extension calculates and when to open it. Use actual screenshots from the current published version; put the calculator result first, followed by a comparison. Do not claim support for untested stores or unpublished features.
2. Share one useful example at a time: e.g., the cost per use of headphones at five uses per week, then at half that frequency. Link to the public calculator and Store listing where community rules permit, and answer questions without repetitive promotion.
3. Make the public website useful on its own. Keep the interactive calculator, direct Store link, privacy explanation, and mobile layout working. Its social preview now uses the existing product example image so shared links explain the tool before a click.
4. Ask satisfied users for honest feedback through the existing support channel. Do not promise incentives for ratings or request reviews before users have tried the extension.

## Measure every two weeks

Use the same 14-day date window before and after each listing or outreach change. Record Store impressions, listing page views, installs, uninstalls, current users, and rating count. Also record the change date and where links were shared. Compare installs per page view only when both numbers cover the same window; compare views per impression only when both definitions and windows are aligned. Small counts will fluctuate, so prefer repeated signals over a single day's movement.

If impressions are low, focus on discovery and relevant communities. If views rise but installs do not, revisit the listing's first screenshot, summary, and trust signals. If installs rise but uninstalls follow, investigate first-use accuracy, setup, and feedback. Dashboard user counts represent installations, not confirmed active use.

Chrome's own guidance: [discovery](https://developer.chrome.com/docs/webstore/discovery), [listing quality](https://developer.chrome.com/docs/webstore/best-listing), and [Store metrics](https://developer.chrome.com/docs/webstore/metrics).
